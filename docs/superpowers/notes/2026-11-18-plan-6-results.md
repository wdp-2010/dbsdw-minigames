## Decisions

1. All art is generated by scripts in `tools/pack_src/` (Pillow and pure-Python synthesis, run in Docker
   via `generate.sh`), so the pack rebuilds byte for byte. Generated files are committed so CI needs no
   extra tools.
2. The first gun looked like a toy and the owner rejected it. It was rebuilt after three real speedball
   markers (long thin barrel, slim body, egg-shaped loader on a feed neck, foregrip, raked grip,
   bottom-line air tank). Its hand transforms were found by comparing variants in the client.
3. Team colours come from `custom_model_data` tints: one model each for the gun, paintball, flag and
   splat, in any team colour. The splat picks its shape and fade stage from `custom_model_data` floats.
4. One chest-menu background covers the whole 3-row chest screen. The slot interiors are transparent, so
   the vanilla slots and items show through whatever order the client draws in.
5. The hit splash is a full-screen font glyph shown as a title (0.3 s, then a 0.4 s fade). It is not
   shown for the hit that puts a player out, because the "Uit!" title uses the title slot.
6. The out paint burst is now shown to the other players only. Seen from inside, it covered the
   victim's whole screen.
7. Power-ups glow in their own colour. The default white glow made them look grey from a distance.
8. Pack ids live in `PackAssets` (one per module). `tools/test_pack_keys.py` fails the build if the pack
   lacks an id or glyph used by the plugins. `build_pack.py` also fails on broken references inside the
   pack.

## Deployment (test servers only)

- Server 5 has a second allocation `62.83.125.228:25600` for the pack HTTP server. It has a ufw rule
  (label only; Docker publishes the port itself) and is in `~/NETWORK-MAP.md`. Config:
  `pack.public-url: "http://62.83.125.228:25600"`.
- New jars and `pack.zip` are on server 5. Both `messages.yml` files were removed so the plugins wrote
  the new defaults with the glyphs. The old files are on node1 in `/root/plan6-backup-2211`.
- **Live survival is untouched.** When live is linked (plan 8), the minigame server's `messages.yml`
  files must be regenerated the same way. The plugins only add missing keys, so changed defaults
  (glyphs) do not reach an existing file.
